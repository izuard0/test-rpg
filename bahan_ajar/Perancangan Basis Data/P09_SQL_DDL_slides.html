Kilas balik

Satu rancangan, tiga tingkat abstraksi

1

Desain konseptual

Entitas, atribut, dan relasi dalam ERD. Fokus pada kebutuhan bisnis, belum memikirkan DBMS.

2

Desain logis

ERD ditransformasikan menjadi skema relasional (PK, FK), lalu dinormalisasi.

3

Desain fisik

Skema ditulis sebagai perintah DDL yang dieksekusi DBMS: tipe data, constraint, indeks.

ERD notasi Chen: satu instruktur mengajar banyak kursus (1:N).

Instruktur(instruktur_id, nama_instruktur, email)
Kursus(kursus_id, nama_kursus, jumlah_modul, instruktur_id)

Garis bawah = primary key; garis putus-putus = foreign key yang merujuk Instruktur.

CREATE TABLE Kursus ( kursus_id INT AUTO_INCREMENT PRIMARY KEY, nama_kursus VARCHAR(150) NOT NULL, jumlah_modul INT, instruktur_id INT NOT NULL, FOREIGN KEY (instruktur_id) REFERENCES Instruktur(instruktur_id) );

Skema yang sama ditulis sebagai perintah yang dapat dieksekusi DBMS.

Structured Query Language

Empat sub-bahasa SQL

DDL

DATA DEFINITION

Mendefinisikan struktur: basis data, tabel, kolom, constraint, indeks, view.

DML

DATA MANIPULATION

Mengelola isi: menambah, membaca, mengubah, dan menghapus baris. Dibahas pada P10.

DCL

DATA CONTROL

Mengatur hak akses: siapa boleh membaca atau mengubah objek apa.

TCL

TRANSACTION CONTROL

Mengelola transaksi: menyimpan atau membatalkan sekumpulan perubahan.

Aturan integritas

Enam constraint utama

PRIMARY KEY

Identitas setiap baris: unik dan tidak boleh NULL. Satu per tabel.

kursus_id INT PRIMARY KEY

FOREIGN KEY

Nilainya harus ada di PK tabel induk (integritas referensial).

FOREIGN KEY (instruktur_id) REFERENCES Instruktur(instruktur_id)

NOT NULL

Kolom wajib diisi.

nama_kursus VARCHAR(150) NOT NULL

UNIQUE

Tidak ada dua baris dengan nilai sama; untuk candidate key.

email VARCHAR(100) UNIQUE

CHECK

Nilai harus memenuhi kondisi logika.

CHECK (jumlah_modul > 0)

DEFAULT

Nilai otomatis bila kolom tidak diisi saat INSERT.

harga DECIMAL(12,2) DEFAULT 0
Tingkat kolom

Ditulis menempel pada definisi kolom; berlaku untuk kolom itu saja.

Tingkat tabel

Ditulis setelah kolom: CONSTRAINT nama ...; dapat mencakup beberapa kolom.

ERD → DDL

Memetakan kardinalitas menjadi FOREIGN KEY

FK + UNIQUE di salah satu sisi

Letakkan pada sisi yang partisipasinya total: setiap profil pasti milik satu instruktur. UNIQUE yang menjaga agar tetap 1:1.

CREATE TABLE ProfilInstruktur ( profil_id INT AUTO_INCREMENT PRIMARY KEY, instruktur_id INT NOT NULL UNIQUE, -- kunci 1:1 bio TEXT, website VARCHAR(255), CONSTRAINT fk_profil_ke_instruktur FOREIGN KEY (instruktur_id) REFERENCES Instruktur(instruktur_id) ON DELETE CASCADE );

FK di sisi N (banyak)

Setiap kursus menyimpan satu instruktur_id. Bila dibalik, satu instruktur harus menyimpan banyak kursus_id dalam satu sel, dan itu melanggar 1NF.

CREATE TABLE Kursus ( kursus_id INT AUTO_INCREMENT PRIMARY KEY, nama_kursus VARCHAR(150) NOT NULL, jumlah_modul INT, instruktur_id INT NOT NULL, -- FK di sisi N CONSTRAINT fk_kursus_instruktur FOREIGN KEY (instruktur_id) REFERENCES Instruktur(instruktur_id) );

Tabel penghubung

Berisi dua FK. Kombinasi keduanya harus unik. Atribut milik relasi (tgl_pendaftaran) ikut disimpan di sini.

CREATE TABLE Pendaftaran ( pendaftaran_id INT AUTO_INCREMENT PRIMARY KEY, mahasiswa_id INT NOT NULL, kursus_id INT NOT NULL, tgl_pendaftaran DATE NOT NULL, -- atribut relasi CONSTRAINT uq_mahasiswa_kursus UNIQUE (mahasiswa_id, kursus_id), CONSTRAINT fk_pendaftaran_mahasiswa FOREIGN KEY (mahasiswa_id) REFERENCES Mahasiswa(mahasiswa_id), CONSTRAINT fk_pendaftaran_kursus FOREIGN KEY (kursus_id) REFERENCES Kursus(kursus_id) );

Studi kasus · skrip DDL

Membangun skema langkah demi langkah

Telaah rancangan

Apakah skrip ini sudah optimal?

🧩

ProfilInstruktur memiliki profil_id dan instruktur_id UNIQUE. Perlukah profil_id?

Klik untuk membuka

Tidak wajib

Karena relasinya 1:1, instruktur_id dapat sekaligus menjadi PRIMARY KEY dan FOREIGN KEY (shared primary key). Satu kolom dan satu indeks berkurang.

🔑

Pendaftaran: surrogate key + UNIQUE(mahasiswa_id, kursus_id), atau PRIMARY KEY(mahasiswa_id, kursus_id)?

Klik untuk membuka

Keduanya sah

PK gabungan lebih ringkas. Surrogate key memudahkan bila baris pendaftaran kelak dirujuk tabel lain (mis. Nilai). Yang wajib: kombinasi mahasiswa–kursus tidak boleh ganda.

🗑️

FK pada Kursus tidak menulis ON DELETE. Apa yang terjadi bila seorang instruktur dihapus?

Klik untuk membuka

Ditolak (RESTRICT)

Penghapusan gagal selama instruktur masih memiliki kursus. Untuk data bernilai, ini justru aman. CASCADE akan ikut menghapus kursus beserta riwayatnya tanpa peringatan.

Praktikum · MySQL 8 / MariaDB

Kegiatan praktikum

🧑‍💻

Bagian A · e-learning · terbimbing

  1. Buat basis data elearning (utf8mb4)
  2. Jalankan skrip lima tabel sesuai urutan
  3. Verifikasi dengan DESCRIBE dan SHOW CREATE TABLE
  4. Uji setiap constraint dengan INSERT yang melanggar, lalu catat kode galatnya
  5. Ubah ProfilInstruktur menjadi shared primary key dengan ALTER
🏗️

Bagian B · proyek kelompok · mandiri

  • Terjemahkan skema relasional hasil normalisasi kelompok menjadi skrip DDL
  • Tetapkan tipe data dan alasannya untuk setiap kolom
  • Tentukan aksi ON DELETE untuk setiap FK beserta justifikasinya
  • Kumpulkan: kelompok_X.sql + tangkapan layar

Rangkuman

Poin-poin utama

🏛️

DDL mewujudkan skema logis menjadi struktur fisik; keputusan desain diambil sebelumnya.

🔢

Tipe data adalah domain: NIM dan nomor HP disimpan sebagai teks, uang sebagai DECIMAL.

🛡️

Constraint membuat DBMS menolak data yang salah, bukan aplikasi yang harus selalu ingat.

🔗

FK di sisi N; M:N memerlukan tabel penghubung. CREATE induk dulu, DROP anak dulu.

🤔

Pertanyaan pemantik: bila data ganda sudah terlanjur masuk sebelum UNIQUE dibuat, apa yang terjadi saat ALTER TABLE … ADD UNIQUE dijalankan? Bagaimana membersihkannya dengan DML?

Evaluasi pembelajaran

Latihan soal

  1. Tulis CREATE TABLE Buku dengan atribut isbn (13 digit), judul, tahun_terbit, harga, dan stok (tidak boleh negatif). Jelaskan pilihan tipe data dan constraint-nya.
  2. ERD: Dosen (1) membimbing (N) Mahasiswa. Di tabel mana FK diletakkan? Tulis DDL kedua tabel.
  3. Relasi M:N Mahasiswa–MataKuliah memiliki atribut nilai. Rancang tabel penghubungnya lengkap dengan PK dan FK.
  4. Tentukan urutan CREATE dan urutan DROP untuk tabel Pendaftaran, Kursus, Instruktur, dan Mahasiswa.
  5. Tulis perintah ALTER untuk: menambah kolom angkatan, menambahkan CHECK angkatan ≥ 2000, dan mengganti nama kolom nama_mahasiswa menjadi nama.
  6. Jelaskan perbedaan DELETE, TRUNCATE, dan DROP dari segi struktur, AUTO_INCREMENT, dan ROLLBACK.

Kunci jawaban tersedia pada catatan pengajar (tekan N).
